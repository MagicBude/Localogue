# JavBoss 对 Localogue 的参考审查

> 审查日期：2026-09-08。依据本机 `D:\Github\jav\JavBoss` 当时的 README、截图和代码。
> JavBoss 使用 GPL-3.0；本文只记录产品思想和独立实现方向，不复制其代码或视觉资源。

## 1. 两个产品解决问题的方式不同

JavBoss 把“扫描 → 在线刮削 → 播放 → 文件操作”做成一条自动流水线，优势是开箱后很快看到结果。Localogue 的核心是 Canonical Library、Evidence、Review、共享资料包与私人覆盖，优势是资料可追溯、可治理，也能完全离线运行。

因此，值得吸收的是**低学习成本的交互**，不是把 Localogue 改成另一套刮削器。在线 Provider、播放器和后台服务即使以后加入，也应通过现有 Application Service 与 Platform Port 扩展，不能绕过 Canonical / Evidence 边界。

## 2. 已立即吸收：真正的瀑布流

JavBoss 的列表没有用一个超大 `pageSize` 假装连续浏览，而是保留后端分页，在用户接近页尾时继续取下一批并累积结果；从详情返回时，如果页面尚未长到原滚动位置，会继续补批次。

Localogue 已按相同产品原理独立实现：

1. `queryWorks` 仍按正常页大小返回，查询语义没有分叉；
2. `IntersectionObserver` 在页尾进入 600px 预取区时请求下一页；
3. 新结果按 Work ID 去重追加；
4. 保留“加载更多”按钮，照顾键盘操作和旧 WebView；
5. 返回深处时先补足文档高度，再恢复滚动位置。

这解释了“瀑布流”的准确含义：用户不必手动翻页，但程序也不应一次把整个资料库塞进 DOM。

## 3. UI 中最值得吸收的部分

| 观察 | JavBoss 的效果 | Localogue 的独立实现方向 | 优先级 |
| --- | --- | --- | --- |
| 卡片底部快捷动作 | 播放、刮削、截图等操作无需先进入详情 | 只保留常用且安全的“播放本地媒体、定位文件、收藏”；次要动作进更多菜单 | 高 |
| 截图浏览弹层 | 不离开当前作品上下文即可看时间点截图 | 将已有截图 Asset 做成轻量灯箱；未来媒体时间点作为独立能力设计 | 高 |
| 目录管理行 | 每个目录可启用、编辑、删除，状态紧凑 | 将 Library Root 从长表单升级为可启停的来源列表；删除继续明确区分“移除配置”和“删除私人资料” | 高 |
| 顶部高密度工具栏 | 搜索、排序、模式与分页集中，反馈直接 | 保持 Localogue 当前吸顶筛选栏，继续减少空白并把低频条件留在抽屉 | 已在进行 |
| 人物卡片事实摘要 | 作品数和基础资料可直接比较 | 人物卡片补作品数、活动状态等最确实有值的字段，不展示空字段 | 中 |
| 设置分区导航 | 大量设置仍能快速定位 | 随设置项增长后采用左侧分区或页内目录；新手模式先显示必要项 | 中 |
| 批量选择与动作 | 大资料库治理效率较高 | 仅在有明确、可撤销语义的任务中加入；删除和文件整理仍需计划与回执 | 中 |

Localogue 不应照搬卡片上的全部按钮。按钮数量过多会让新手先理解工具，而不是先浏览作品。默认界面只呈现最常用动作，高级功能通过详情页或“更多”展开。

## 4. 功能中值得进入路线的部分

### 4.1 近期可以做

- **媒体版本选择后播放**：一部 Work 有多个 MediaFile 时先展示分辨率、文件大小和路径，再调用现有受限 `open_path`；单文件可以直接播放。
- **截图 Asset 灯箱**：缩略图、原图查看、设为私人封面，删除继续走可恢复销与引用检查。
- **资料根目录启停**：临时离线的硬盘无需删除配置；扫描只处理启用且可访问的根。
- **扫描状态摘要**：首页显示上次完成时间、发现/新增/更新/缺失/警告，详细信息进入现有扫描历史。
- **卡片密度偏好**：海报墙与瀑布流分别保存大小，默认值适合新手，高级设置仍保留。

### 4.2 需要先设计边界

- **播放进度与断点续播**需要新的私人 Playback State，不能写入 Canonical Work，也不能假设所有默认播放器都会回传进度。
- **定时扫描**应建立后台 Job / Scheduler，并提供硬盘保护、互斥执行与可观察状态；不能用页面定时器无限调用同步扫描。
- **文件整理、重命名、批量删除**必须继续遵循非破坏性默认策略，先生成预览计划并允许逐项排除。
- **远程 / NAS 模式**会引入身份验证、路径映射、网络失败与服务生命周期，属于独立发布阶段。

### 4.3 当前阶段不吸收

- 在线站点自动刮削与浏览器扩展：当前 V1 要求核心功能离线，外部来源必须先形成 Evidence；
- 内嵌播放器、转码服务器和 MPV 深度控制：当前产品约束明确不实现播放器与复杂微服务；
- SQLite 直接替换 JSON Repository：大规模性能数据出现后按既有 V2 Storage Adapter 路线迁移；
- 扫描结果直接覆盖作品：这会破坏 Evidence → Review → Canonical 的可信链路。

## 5. 建议的实施顺序

1. 完成 Works 浏览稳定性：渐进瀑布流、返回位置、卡片密度和多资料库切换。
2. 优化日常动作：单文件直接播放，多文件选择，定位文件，截图灯箱。
3. 简化资料源管理：根目录卡片、启停、可访问状态、移除与真实删除的清楚提示。
4. 汇总扫描反馈：首页轻摘要，历史页看完整日志与警告。
5. 再评估 Playback State、定时任务和文件整理计划；每项先建立 Domain / Port 边界。

这条顺序先降低普通用户每天都会遇到的操作成本，同时保留 Localogue 已经建立的资料可信与审计能力。
