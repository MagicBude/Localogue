# UI 信息架构

## Desktop 主导航

Desktop 一级导航按用户任务组织，避免把领域实体和治理内部模块平铺成后台菜单：

- 首页：最近作品、资料库摘要和继续整理入口；
- 资料库：作品、人物、分类浏览和我的收藏；
- 导入与整理：进入一张连续工作台；
- 资料维护：资料问题、变更历史；
- 设置：进入设置页后改用顶部模块导航；资料包导入、导出和备份从“共享资料”模块进入。
- 关于：固定在窄栏最底部，集中展示版本、运行环境、程序日志与本机设置位置。

一级任务区只负责全局功能导航，默认采用类似 Fluent 桌面应用的 68px 窄栏；每个入口固定为图标在上、短文字在下，不依赖用户悬停猜测含义，用户仍可按偏好展开。设置入口固定在功能区底部。资料库、资料维护和设置的并列页面全部使用同一条顶部标签栏，左侧不再展开第二种子导航。导入与整理当前只有一张连续工作台，因此不显示只有一个选项的空洞标签栏。

导航图标统一来自 `@fluentui/react-icons`；窄栏提示使用 Radix Tooltip 处理鼠标、键盘焦点和 Portal。第三方组件只承担图标与底层交互，Localogue 自己的 UI Primitive 和 CSS 继续控制视觉语言，避免页面直接拼装不同组件库的默认主题。

顶部二级导航统一通过 `ContextTabBar` 渲染，标签、Fluent 图标、当前状态与键盘语义保持一致。页面只提供导航项目和选择动作，不得各自复制一套顶部标签 CSS 或在标签组件内部另存路由状态。

详情页的“返回”按照真实访问历史逐级回退：例如从作品进入人物，再返回时应回到原作品，而不是跳到人物库。Desktop 宿主使用轻量位置栈保留这条路径，切换全局一级页面时才清空。

应用顶栏不重复展示页面大标题，只保留产品版本、语言与全局操作；页面标题采用桌面应用尺寸。主要操作统一使用 Fluent 蓝色，普通按钮保持浅色，所有键盘焦点使用同一可见轮廓。

Desktop 基础控件采用渐进式 Primitive：按钮统一 default / primary / danger / ghost 语义和 loading 状态，输入与选择统一可访问标签、辅助说明和错误关联，短进度反馈与空状态使用独立组件。页面仍拥有业务动作与数据状态，Primitive 不读取 Repository、不调用 Native Command，也不以一次性全量替换制造高风险 UI 重写。

资料库重命名、删除等需要输入或确认的操作使用统一应用内对话框，不调用浏览器原生 prompt / confirm。危险选项不得成为默认值：删除 Profile 默认只移除配置，删除 Localogue 受管数据需要在同一对话框内额外明确勾选，并继续排除用户的影片内容根目录。

普通 Desktop 设置采用自动保存：目录选择与列表增删立即保存，文本字段在离开输入框或按 Enter 后保存。自动保存请求按用户操作顺序串行落盘；Profile 切换必须携带当前界面中的最新全局设置，不能用旧快照覆盖刚输入的值。全局消息显示在顶栏下方的右上角浮层，不占据正文高度；成功/普通消息短暂停留后淡出，需要用户处理的错误和警告持续显示，并允许用户主动关闭。

“关于”使用与设置页一致的单列 Fluent 设置行。设置模块中的原“关于与诊断”收敛为“诊断”，避免同一内容在两个入口重复出现；关于页不展示尚未实现的在线更新、授权或反馈按钮。

Web 当前继续保留已有 URL 信息架构。Desktop 是本地日常使用的主要入口，Web 是否长期保留完整功能对齐将在后续产品阶段单独决定。

## 导入与整理流程

“导入与整理”是一张连续工作台。Desktop 按用户实际处理顺序，把资料来源摘要、统一目录同步、媒体扫描、NFO / 图片预览导入和 Evidence 核对纵向放在同一页面。用户完成一个动作后可以直接向下继续处理，不需要先理解系统内部模块，也不需要在扫描页与审核页之间来回跳转。

资料来源配置和最终作品浏览仍可从工作台进入，因为它们属于低频前置设置和结果查看，不强行塞进日常处理区。扫描终态、Evidence 生命周期、Commit Plan blocker 等完成条件继续由各自 Application Service 负责；工作台只组合既有能力，不在 Presentation 中另造业务状态。

普通用户添加或移除内容目录后立即保存，不需要滚到设置页底部再提交。统一同步在工作台固定显示“发现文件、导入资料与图片、扫描视频、完成”四个执行阶段；媒体扫描阶段继续显示 Application Job 提供的当前数量与总数。

内容目录的长期管理入口统一放在设置的“资料库与目录”模块。工作台只读取已配置目录并执行同步，不再提供新增或移除入口。首次空状态继续由 Quick Setup 自动创建受控 Private Library，用户只选择一次自己的内容目录；初始化完成后，后续目录维护都回到同一设置模块。

工作台以只读目录卡片完整展示当前 Profile 已添加的每个内容目录，包含视频数、已关联/未关联数和最近一次包含该目录的扫描时间。用户可以同步全部目录，也可以对单个目录执行完整的 NFO → Asset → Media 增量同步；“管理内容目录”明确返回唯一设置入口。单目录扫描的缺失清理只作用于本轮成功扫描的根，不会把其他目录的 MediaFile 误判为已删除。

设置页按职责拆成“资料库与目录、共享资料、扫描与工具、关于与诊断”四个顶部模块。默认页面只突出当前资料库和内容根目录；路径概念说明与 Private 存储位置折叠为按需查看的辅助项。模块切换只改变当前设置的展示范围，不建立第二套配置模型。

作品库的“内容目录”筛选来自 Private MediaFile 的 `scanRoot`。选择一个目录只显示在该目录拥有本地媒体的作品；选择多个目录显示并集。同一作品存在于多个目录时只展示一次。该条件进入共享 `WorkQuery` 并遵守 self-excluding Facet 计数，不把本机路径写入 Canonical Work。

## 设计目标

- 浏览优先，不做传统“后台管理系统”视觉；
- 信息密度高，但层级清楚；
- 海报和人物图是重要视觉资产；
- 筛选器在桌面端高效，在移动端可折叠；
- URL 尽可能保存查询状态。

## V1-11 新入口

```text
/packs
/media/[mediaFileId]
```

`/packs` 管理 Shared/Personal Portable Pack；`/media/[id]` 负责单个本地媒体文件的人工作品绑定治理。
