# UI 信息架构

## 用户术语

普通界面以 [用户用语规范](../product/user-terminology.md) 为准，只使用五个核心概念：影片库、内容目录、社区资料、待审核资料和个人备份。`Library Profile / Private Library / Shared Pack / Canonical / Evidence / Commit Plan` 保留为代码、Schema、开发文档或高级诊断词，不作为普通任务入口名称。

其中“影片库”合并旧 UI 中的“资料库 / Library Profile / 私人资料库”心智概念；“社区资料”合并“公共资料 / 共享资料 / Community Catalog”，其磁盘发布容器仅在导入导出时称“社区资料包”。动作统一称“扫描资料库”，只有数据库投影或远端镜像等真实同步语义继续使用“同步”。

## Desktop 主导航

Desktop 一级导航按用户任务组织，避免把领域实体和治理内部模块平铺成后台菜单：

- 首页：最近作品、影片库摘要和继续整理入口；
- 作品、人物、分类浏览、目录与扫描：作为日常浏览和整理任务直接进入；
- 收藏：直接进入当前影片库的私人收藏；
- 资料维护：资料问题、变更历史；
- 设置：进入设置页后改用顶部模块导航；社区资料包和个人备份从“社区资料”模块进入。
- 关于：固定在窄栏最底部，集中展示版本、运行环境、程序日志与本机设置位置。

一级任务区只负责全局功能导航，默认采用类似 Fluent 桌面应用的 68px 窄栏；每个入口固定为图标在上、短文字在下，不依赖用户悬停猜测含义，用户仍可按偏好展开。设置入口固定在功能区底部。作品、人物、分类浏览、目录与扫描不再在内容顶部重复一条影片库标签栏；资料维护和设置包含多个内部模块，进入任务后才显示统一的顶部二级标签。

作品、人物与分类浏览采用同一工作区分层：窗口标题栏承担当前页面搜索，页面首行是独立工具条，中部是带清晰边框的唯一结果框，分页只属于结果框底部。工具条、结果滚动区和分页不得通过 fixed / sticky 跨越彼此边界；单页隐藏翻页与跳转，但保留右侧每页数量。分类浏览的所有分组放在同一个结果框内，用分隔线表达分组，不再为每组叠加一张阴影卡片；题材维度切换固定在该结果框的滚动顶部。

结果底栏采用稳定三段语义：左侧始终显示当前查询总数，中间分页、跳页和页数只在总数超过一页时出现，右侧“每页显示”始终固定。改变结果数量不得让右侧控件换位。作品与人物筛选统一收敛为工具条中的单一“筛选”入口；点击后打开锚定工具条的临时面板，条件即时更新，关闭面板只收起界面而不清除条件，结果内容区不因面板开合重新排版。

导航图标统一来自 `@fluentui/react-icons`；窄栏提示使用 Radix Tooltip 处理鼠标、键盘焦点和 Portal。第三方组件只承担图标与底层交互，Localogue 自己的 UI Primitive 和 CSS 继续控制视觉语言，避免页面直接拼装不同组件库的默认主题。

顶部二级导航统一通过 `ContextTabBar` 渲染，标签、Fluent 图标、当前状态与键盘语义保持一致。页面只提供导航项目和选择动作，不得各自复制一套顶部标签 CSS 或在标签组件内部另存路由状态。

详情页的“返回”按照真实访问历史逐级回退：例如从作品进入人物，再返回时应回到原作品，而不是跳到人物库。Desktop 宿主使用轻量位置栈保留这条路径，切换全局一级页面时才清空。

应用顶栏不重复展示页面大标题，只保留产品版本、语言与全局操作；页面标题采用桌面应用尺寸。主要操作统一使用 Fluent 蓝色，普通按钮保持浅色，所有键盘焦点使用同一可见轮廓。

Desktop 基础控件采用渐进式 Primitive：按钮统一 default / primary / danger / ghost 语义和 loading 状态，输入与选择统一可访问标签、辅助说明和错误关联，短进度反馈与空状态使用独立组件。页面仍拥有业务动作与数据状态，Primitive 不读取 Repository、不调用 Native Command，也不以一次性全量替换制造高风险 UI 重写。

影片库重命名、删除等需要输入或确认的操作使用统一应用内对话框，不调用浏览器原生 prompt / confirm。危险选项不得成为默认值：移除影片库默认只移除配置，删除 Localogue 管理数据需要在同一对话框内额外明确勾选，并继续排除用户的内容目录。

普通 Desktop 设置采用自动保存：目录选择与列表增删立即保存，文本字段在离开输入框或按 Enter 后保存。自动保存请求按用户操作顺序串行落盘；Profile 切换必须携带当前界面中的最新全局设置，不能用旧快照覆盖刚输入的值。全局消息显示在顶栏下方的右上角浮层，不占据正文高度；成功/普通消息短暂停留后淡出，需要用户处理的错误和警告持续显示，并允许用户主动关闭。

作品“瀑布流”是连续浏览模式：接近页尾时自动预取下一批，不显示传统上一页/下一页。列表与表格仍保留分页，以便精确定位和降低大数据集的 DOM 成本；所有视图继续共享同一 WorkQuery 与 Facet 语义。

作品“海报墙”采用横向封面的整卡密集布局：用户首图偏好优先，否则优先合法 `cover` 再回退当前首图；封面下方按番号 + 作品类型、两行标题、日期/时长/厂商、人物、题材/私人标签的顺序展示。人物最多直接展示 3 位，题材与标签合计最多直接展示 6 项，其余使用 `+N` 表达，避免合集把整行卡片撑高。人物与分类 Chip 是独立操作，可直接进入人物或收窄当前 WorkQuery；题材和私人标签使用不同颜色，但不因视觉合并两者的 Domain 语义。瀑布流继续使用竖版首图和连续加载，承担不同浏览任务。

海报墙的人物 Chip 同时提供键盘可访问的延迟预览，优先展示活动状态、出生日期、身高和有限数量的别名。预览只使用已载入的 Canonical Person，不因悬停发起额外文件读取或网络请求。

作品编辑的多值关系使用“已选 Chip + 可搜索候选”，不要求用户按住 Ctrl / Cmd 操作原生多选框。每部 Work 可在同一表单中创建并选中私人 Tag；新 Tag 在保存时先于 Work 写入 Private Library，避免 JSON Repository 短暂出现悬空引用。Genre 仍是受控词表，不在这个入口自由创建。

“关于”使用与设置页一致的单列 Fluent 设置行。设置模块中的原“关于与诊断”收敛为“诊断”，避免同一内容在两个入口重复出现；关于页不展示尚未实现的在线更新、授权或反馈按钮。

关于页提供随安装包分发的中日英离线使用教程，覆盖配置、同步、浏览、编辑、备份和更新。版本说明明确标注尚未支持自动检查/安装更新；源码用户可直接查看 BAT 构建与 EXE 输出路径。帮助和标签管理等长对话框的正文独立滚动，底部操作保留在可视范围。

Web 当前继续保留已有 URL 信息架构。Desktop 是本地日常使用的主要入口，Web 是否长期保留完整功能对齐将在后续产品阶段单独决定。

## 导入与整理流程

内容来源统一为一组“内容目录”。每个目录可以独立启用视频、NFO 和图片扫描，视频与元数据分盘不再通过第二、第三套目录列表表达。普通新增目录默认全部启用；范围开关属于同一目录的高级属性。

“导入与整理”是一张连续工作台。普通用户只需要“扫描资料库”：它会依次检查 NFO、图片和视频，并把新增内容加入当前资料库。“仅检查视频文件”不读取 NFO 和图片，只用于排障，折叠在高级区域。用户不需要先理解 Unified Sync 与 Media Scan 的内部差异。

资料来源配置和最终作品浏览仍可从工作台进入，因为它们属于低频前置设置和结果查看，不强行塞进日常处理区。扫描终态、Evidence 生命周期、Commit Plan blocker 等完成条件继续由各自 Application Service 负责；工作台只组合既有能力，不在 Presentation 中另造业务状态。

普通用户添加或移除内容目录后立即保存，不需要滚到设置页底部再提交。统一同步在工作台固定显示“发现文件、导入资料与图片、扫描视频、完成”四个执行阶段；媒体扫描阶段继续显示 Application Job 提供的当前数量与总数。

内容目录的长期管理入口统一放在设置的“资料库与目录”模块。工作台只读取已配置目录并执行同步，不再提供新增或移除入口。首次空状态继续由 Quick Setup 自动创建受控 Private Library，用户只选择一次自己的内容目录；初始化完成后，后续目录维护都回到同一设置模块。

工作台以只读目录卡片完整展示当前 Profile 已添加的每个内容目录，包含视频数、已关联/未关联数和最近一次包含该目录的扫描时间。用户可以同步全部目录，也可以对单个目录执行完整的 NFO → Asset → Media 增量同步；“管理内容目录”明确返回唯一设置入口。单目录扫描的缺失清理只作用于本轮成功扫描的根，不会把其他目录的 MediaFile 误判为已删除。

设置页按职责拆成“影片库与目录、社区资料、扫描与工具、关于与诊断”四个顶部模块。默认页面只突出当前影片库和内容目录；数据存储位置折叠为按需查看的辅助项。模块切换只改变当前设置的展示范围，不建立第二套配置模型。

作品库的“内容目录”筛选来自 Private MediaFile 的 `scanRoot`。选择一个目录只显示在该目录拥有本地媒体的作品；选择多个目录显示并集。同一作品存在于多个目录时只展示一次。该条件进入共享 `WorkQuery` 并遵守 self-excluding Facet 计数，不把本机路径写入 Canonical Work。

## 右上角

- 全局搜索；
- UI 语言；
- 元数据语言偏好；
- 主题；
- 设置入口。

## 设计目标

- 浏览优先，不做传统“后台管理系统”视觉；
- 信息密度高，但层级清楚；
- 海报和人物图是重要视觉资产；
- 筛选器在桌面端高效，在移动端可折叠；
- URL 尽可能保存查询状态。

## V1-11 新入口

```text
/packs
/media/[mediaFileId]
```

`/packs` 管理 Shared/Personal Portable Pack；`/media/[id]` 负责单个本地媒体文件的人工作品绑定治理。
