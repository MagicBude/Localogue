# 人物库

V1 重点优化演员浏览，同时保留 Person 通用模型。

## 卡片信息

- 主头像；
- 日文正式名；
- 当前语言名称；
- 当前状态；
- 出道时间；
- 作品数量。

## 筛选

- 在役 / 引退 / 休止 / 未知；
- 出道年份；
- 出生年份；
- 是否有头像；
- 作品数量；
- 资料完整度。

## 搜索

搜索必须覆盖：正式名、中文映射、罗马字、旧艺名、别名、曾用名。

## V1-03 实现补充

人物库第一批高级筛选包括：

- 所有姓名类型搜索：正式名、本地化名称、罗马字、别名、旧艺名、曾用名和其他写法；
- 当前活动状态；
- 出生年份；
- 出道年份；
- 引退年份；
- 身高最小值 / 最大值；
- 姓名、出生时间、出道时间、身高排序；
- URL 分页。

职业年份来自 `careerEvents`，不会额外复制成互相可能不一致的简单字段。

## Desktop 当前交互

人物页与作品页使用同一套顶部筛选骨架：

- 姓名 / 别名搜索位于窗口标题栏，排序固定在页面工具条；
- 其余条件统一收进单一“筛选”浮窗，包含活动状态、出道 / 引退 / 出生年份、身高范围、出生地、罩杯，以及人物图片、出生日期、身高、三围和简介的“有 / 无”资料条件；
- 已选条件在结果数量上方显示为可单独移除的 Chips；
- 底栏左侧固定显示人物总数，超过一页时才显示分页，右侧每页数量保持固定；
- 窄窗口允许工具栏自然换行，不使用页面级横向滚动遮盖控件。

筛选条件仍由共享 `queryPeople` 语义执行，UI 的收纳方式不会改变查询、分页或人物姓名全量匹配规则。

人物详情首屏同时容纳头像、状态、名称、简介和四项核心事实。编辑入口位于首屏操作区，并在独立对话框中完成；编辑表单不再作为正文大卡片展开，相关作品和人物图片因此能更早进入可视区域。
