# 重复检测

## 1. 基本原则

V1-08 只生成 `DuplicateCandidate`：

```text
候选发现 ≠ 自动确认重复 ≠ 自动合并
```

任何自动合并都会影响 Work → Person、Work → Genre、Provenance、历史 Receipt 等大量引用，因此未来必须通过独立 Merge Plan 才能执行。

## 2. Work 候选规则

当前可解释规则：

1. 规范化番号完全一致 → `high`；
2. 原始标题完全一致 + 发行年份一致 → `medium`；
3. 上述条件再加共同演员 → `high`；
4. 原始标题完全一致 + 共同演员 → `medium`。

番号规范化会：

- Unicode NFKC；
- 转大写；
- 去除连字符、空格和其他非字母数字字符。

标题规范化会：

- Unicode NFKC；
- 小写；
- 去除空白、标点与符号。

## 3. Person 候选规则

当前只使用保守的精确信号：

- 两个 Person 的任意正式名 / 译名 / 罗马字 / 旧艺名 / 别名规范化后完全相同 → `medium`；
- 上述条件同时出生日期相同 → `high`。

不使用：

- 编辑距离；
- 拼音猜测；
- 自动简繁转换；
- AI 模糊合并。

## 4. 后续演进

未来可加入：

- 外部稳定人物 ID；
- 媒体 SHA-256；
- Asset 感知哈希；
- 更精细的同名人物消歧；
- Merge Plan 与引用迁移。
