# 核心设计原则

## P01：Canonical Library 是最终真相源

进入正式资料库后，作品、人物和关系的最终状态由 Localogue 的 Canonical Library 决定。

## P02：Evidence 与正式资料分离

NFO、JSON、CSV、API 响应、人工提交都先视为 Evidence。Evidence 可以互相冲突，正式资料不能因为某一次导入而被无条件覆盖。

V1-16 为用户已有的本地 NFO 存量资料提供一个窄范围 Bootstrap Ingest 例外：必须先 Preview、再明确确认，且已有 Work 只能 fill / merge，不能覆盖既有核心事实。这个迁移例外不改变长期 Evidence / Review 原则，也不推广到在线 Provider 或一般编辑。

## P03：原文优先且永久保留

日本作品默认保留日文原始标题、名称和简介。中文、英文是映射或翻译，不得覆盖原文。

## P04：实体关系优先于字符串

演员、导演、Maker、Label、Series、Genre 等应成为实体或受控关系，而不是最终存成逗号字符串。

## P05：Work 与 MediaFile 分离

作品是逻辑实体，媒体文件是本地载体。一个作品可没有文件，也可有多个版本文件。

## P06：分类体系职责分明

- Work Type：作品形态/形式；
- Genre：作品内容或行业分类；
- Tag：用户自己的整理标签。

三者不可混用。

## P07：浏览能力是一等功能

多维筛选、排序、时间线、动态 Facet 计数和实体间跳转不是附加功能，应在数据模型阶段就考虑。

## P08：V1 简单但不短视

V1 使用 JSON，不意味着页面到处直接读文件。通过 Repository 抽象，让 V2 能替换为 SQLite。

## P09：默认非破坏性

扫描已有目录时默认只建立索引，不移动、不重命名、不删除用户文件。

## P10：离线优先

本地资料浏览、筛选、编辑、审核、导入和导出不能依赖互联网。

## P11：可追溯

重要字段尽量能追踪来源、导入时间、原始值和人工覆盖情况。

## P12：文档与代码同步

架构、词表、字段和行为变化必须同步文档，避免项目知识只存在聊天记录。
