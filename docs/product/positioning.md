# 产品定位

## 一句话定位

**Localogue 是一款本地优先的 AV 个人资料库与策展管理器：扫描并关联本地媒体，叠加可信公共元数据与私人修订，支持浏览、筛选、编辑、备份和委托播放。**

这句话也是仓库介绍的推荐文案。它先说明用户得到什么，再说明 Localogue 的数据原则；“策展”是保证资料可信的方法，不应成为普通用户上手前必须理解的概念。

## 正式产品形态

Localogue Desktop 是面向普通用户的正式入口。用户应在一个窗口内完成：

1. 首次选择一个或多个内容目录；
2. 查看可见、可取消的增量扫描进度；
3. 检查识别结果，处理未识别、冲突和多版本媒体；
4. 浏览、筛选、收藏和编辑作品与人物；
5. 叠加公共 Catalog 与私人修订；
6. 使用系统默认程序或用户指定播放器打开视频；
7. 备份和恢复私人资料。

Web 入口目前是历史功能宿主与开发验证入口。是否退役按 [ADR-047](../decisions/ADR-047-desktop-primary-product-and-web-retirement.md) 单独决策，不能在能力尚未迁移完成时直接删除。

## 产品价值

- **开箱即用**：默认值应能工作，普通用户不需要理解 JSON、SQLite、Evidence 或 Repository；
- **零侵入**：默认不移动、不重命名、不删除用户视频，运行数据与媒体目录分离；
- **本地闭环**：核心浏览、编辑和播放入口离线可用；
- **资料可信**：来源证据、公共整理结果和私人修订分层保存，外部数据不能静默覆盖用户选择；
- **AV 专用**：番号、多段、版本、人物别名、Maker / Label / Series 和分类均使用结构化模型；
- **可迁移**：SQLite 服务运行时查询，JSON / CSV 服务交换、审核和恢复。

## 与 JavBoss 的关系

JavBoss 当前在日常使用体验上更成熟。Localogue 应学习它的零配置、流程闭环、目录管理、明确反馈、零侵入和紧凑 UI。用户打开软件后能否立即完成任务，比内部模型有多完整更重要。

Localogue 不应机械复制 JavBoss 的全部范围。通用视频模式、CloudDrive2、磁力下载和内嵌 MPV 会同时引入账号、网络、下载、解码、跨平台打包和安全边界；这些能力只有在核心 AV 资料库已经稳定、且真实需求足够明确时再独立评估。

## 与刮削器的关系

完整产品最终需要“取得元数据”的能力，否则用户仍要在多个软件之间切换。Localogue 不应把网页解析规则散落到 UI，也不应让 Provider 直接覆盖 Catalog。

[ADR-048](../decisions/ADR-048-controlled-metadata-acquisition-adapters.md) 提议采用受控 Adapter：外部工具或独立进程负责采集，Localogue 通过版本化协议接收结果并保存为 Evidence，再由规范化、匹配和审核管线进入 Catalog 或私人层。该方向尚未等同于已经实现在线刮削。

## 明确边界

Localogue 聚焦 AV 个人资料库，不以通用影视管理、云端 SaaS、下载器、转码服务器或多用户媒体服务为当前目标。委托播放属于核心闭环；内嵌解码和流媒体服务不是 0.2 的前置条件。
