# ADR-050：Settings V2 以影片库 Profile 作为路径配置唯一来源

## 状态

已接受（2026-09-14）。

## 决策

Desktop 设置使用 `schemaVersion: 2`。所有资料路径都属于 `libraryProfiles[].`：

- `libraryPath`：当前影片库的私人资料存储位置；
- `contentFolders`：原始内容目录及视频、NFO、图片扫描范围；
- `sharedPackPaths`：只读社区资料来源及其优先级。

全局设置只保留 UI/运行时偏好，例如 Web URL、ffprobe 路径和当前 Profile ID。页面、扫描器、Repository 与 Rust Native Boundary 都从当前 Profile 读取路径，不再维护全局路径镜像。

## 迁移与兼容边界

Native 读取旧设置时执行一次内存迁移：旧的全局路径和旧 Profile 路径合并为 `contentFolders`，然后返回 V2。下一次保存只写 V2 JSON，不再写回旧字段。旧版本 EXE 不保证能够读取新的设置文件；这是当前单用户开发阶段接受的破坏性配置升级。

迁移只改变设置配置，不删除原始视频、内容目录、私人资料或社区资料。保存仍使用临时文件加原子替换。

## 原因

同一目录在“资料库、额外媒体目录、额外 NFO 目录、导入页”重复出现，会造成入口冲突、切换 Profile 时状态漂移和扫描范围解释不一致。Profile 作为唯一所有者可以让“选择当前影片库 → 添加内容目录 → 扫描资料库”的流程保持连续，也为未来 SQLite / 多资料库查询提供稳定边界。

## 后果

实现更简单，Profile 切换不会再依赖隐藏的路径同步；代价是旧版本程序不能继续写入 V2 设置。用户可以通过导出个人备份恢复实体资料，但设置迁移本身不提供旧格式回写。
