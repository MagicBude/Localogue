# ADR-013：V1 实体匹配采用保守的规范化精确匹配

## 状态

已接受。

## 背景

Evidence 中的人物、Maker、Label、Series、Genre 等通常以字符串出现，而 Canonical Library 使用稳定实体 ID。

系统需要 Entity Resolution，但错误地把两个不同实体合并，比暂时留下一个未匹配候选更危险。

## 决策

V1-05 自动匹配只允许：

1. 对输入进行 Unicode NFKC、大小写和空白规范化；
2. 在明确实体类型范围内查找；
3. 唯一精确命中时标记 `matched`；
4. 多个精确命中时标记 `ambiguous`；
5. 无命中时标记 `new`；
6. 不使用编辑距离、拼音、AI 或其他模糊推断自动绑定实体。

人物的正式名、本地化名、罗马字、旧艺名、别名、曾用名等全部可以作为精确匹配入口。

## 后果

优点：

- 显著降低错误合并风险；
- 行为可解释；
- Review 页面可以明确展示为什么匹配；
- 后续可以安全加入“候选建议”而不改变自动绑定规则。

代价：

- 一些本来可以猜中的拼写差异会暂时成为 `new`；
- 用户需要更多人工 Review；
- 未来需要专门的 Alias 维护和候选建议能力。

这些代价符合 Localogue 的优先级：

> 数据可信 > 自动化程度。
